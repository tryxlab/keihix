# 【KeihiX開発日記#6】DriveのCSVからスマホ向け収支サマリ・AI質問・重複削除まで。OSS×買い切り配布を見据えた仕上げログ

個人開発者や副業エンジニアが直面する確定申告の壁。
「領収書の整理が面倒」「でも月額課金のクラウド会計ソフトを入れるほど取引件数は多くない」という課題を解決するため、サーバー代0円・個人情報保持ゼロのAndroidアプリ **「KeihiX」** を自作しています。

* **第1回:** 【構想・設計編】月額課金したくない個人開発者が、サーバー代0円・個人情報保持ゼロの「レシート＆収入管理アプリ」を設計した話
* **第2回:** 【電帳法＆免責編】高価なタイムスタンプは不要？個人事業主が電帳法を合法ハックする事務処理規程とCLI実機開発
* **第3回:** 【AI抽出・BYOK編】Geminiで領収書＆売上明細をパースする。Structured OutputsとBYOKの実装ログ（実測3.0秒）
* **第4回:** 【Google Drive直結編】Google Driveを自作DBにする。drive.fileスコープとCSV追記（Read-Modify-Write）の実装ログ
* **第5回:** 【Android UX編】実機の503エラー・OAuth同意・重複保存の罠を越えて。共有インテントとWorkManager、「あとで解析」のUX実装ログ

前回（#5）までは「日々の領収書やPDFを撮って Google Drive に溜める」ところまで作りました。
ただ、せっかく `transaction_log.csv` を Drive に蓄積できても、これまでのアプリには **「溜めたデータを振り返って集計し、確定申告に向けて出力する画面」** がありませんでした。

第6回となる今回は、 **「スマホの縦画面で見やすい収支サマリ＆CSV共有」** 、すでに登録済みの API キーを活かした **「台帳データへの AI 質問＆安全な重複削除」** 、さらに将来の Play ストア配布を見据えた **「API キー設定ガイド・購入前注意喚起」** までを一気に仕上げた開発ログです。

## 1. 「あくまでスマホで見やすく」を軸にした 3 タブ設計

確定申告のための集計画面というと、PC 向けの広い表や円グラフを思い浮かべがちですが、KeihiX は Android アプリです。電車の中やちょっとした隙間時間に片手で確認できるよう、 **横スクロールなし・縦画面完結の 3 タブ構成** にしました。

```text
[収支サマリ・AI質問画面]
  ├── 年別切替バー（< 2026年分 3件 >）
  ├── タブ1: サマリ（差引収支カード / CSV共有 / 転記コピー / 横バーグラフ）
  ├── タブ2: 明細（すべて・経費・収入フィルタ / 1件1カード / 個別削除）
  └── タブ3: AI質問（ワンタップ質問チップ / チャット / 削除提案ボタン）
```

### 円グラフではなく「横バー＋数値」を選んだ理由
科目別の内訳は、見栄えのする円グラフや折れ線グラフのライブラリを入れる選択肢もありましたが、あえて Material 3 のカード内に **「科目名（件数） / 金額 / 割合％ / 横プログレスバー」** を縦に並べる表現にしました。
スマートフォンの狭い横幅では、円グラフの凡例やラベルが潰れたり折り返したりしやすいためです。横バーであれば科目名が長くなっても 1 行に収まり、どの科目がどれだけ使われているかを一目で比較できます。

### 確定申告への転記を意識した 2 つの出力ボタン
サマリタブの上部には、用途に合わせて 2 つのボタンを置きました。

* **CSV共有:** `FileProvider` と `ACTION_SEND` を使い、Google Drive から読み込んだ `transaction_log.csv` をそのままメーラーや他アプリへ渡せます。
* **サマリコピー:** 年次の収入合計・経費合計・差引収支・科目別小計・月別推移をプレーンテキストに整形してクリップボードへコピーします。国税庁の確定申告書等作成コーナーへ転記する前の下書き確認にそのまま使えます。

## 2. 既存の BYOK キーを活かした「自分の台帳への AI 質問」

実装を進めていてふと気づいたのが、 **「このアプリ、すでにユーザーが自分の Gemini API キーを登録しているのだから、集計データについて AI に直接質問することもできるのでは？」** ということでした。

そこで今回、 `GeminiTransactionAdvisor` を追加し、Drive から読み込んだ `transaction_log.csv` を相手に自然言語で質問できる **「AI質問」** タブを組み込みました。

### 計算ミスを防ぐ「事前計算サマリ ＋ 明細CSV」の二段渡し
LLM に生の CSV だけを渡して「経費の合計は？」と尋ねると、件数が増えたときに足し算を取り違えるリスクがあります。
そこで KeihiX では、以下の 2 つを両方プロンプトに含める設計にしました。

* **アプリ側で厳密に計算した集計サマリ（ `TransactionSummaryCalculator` ）:** 収入合計、経費合計、差引収支、手数料・源泉徴収税合計、科目別・月別小計を Kotlin 側で事前計算して渡す。
* **明細データ（最大直近 500 件）:** 個別の取引日、金額、取引先、科目、メモなどを検索・比較用に渡す。

これにより、合計額の算出はプログラム側の確定値を使いつつ、「支出が多い上位3件は？」「重複していそうな取引はある？」「10月のガソリン代はいくら？」といった柔軟な確認を Gemini に任せられるようになりました。

## 3. 実機テストから生まれた 2 つの追加改修

実際に Pixel 9a へビルドを流し込んで動かしてみたところ、 **「これがあると実運用でだいぶ助かる」** というポイントが 2 つ見えてきました。

### ① AI の重複チェックから「そのまま安全に削除したい」
実機でプリセットの「重複チェックして」を試し、続けて重複分の削除を頼んでみたところ、最初は Gemini が「削除したと仮定したシミュレーション値」を返してくれました。

![実機でのAI質問タブ（重複チェックの応答）](../Docs/images/ui_ai_qa_duplicate_check.png)
*▲ 開発途中の実機画面。AI が重複を検出し、削除後のシミュレーション計算まではしてくれた状態*

ここで **「せっかく重複を見つけてくれたなら、そのまま台帳から消せるようにしたい」** と考え、安全性を保ちつつ削除できる仕組みを追加しました。

* **AI が勝手に Drive を書き換えない（Human-in-the-Loop）:**
  プロンプトに各明細の `row_id` を添えておき、ユーザーが削除を希望した場合だけ AI の回答末尾に `[[DELETE_ROWS:2]]` のようなタグを出力させます。アプリ側でこのタグを除去したうえで **「提案された ◯ 件を台帳から削除」** ボタンを表示し、さらに確認ダイアログで日付・取引先・金額を確認して「削除する」を押したときだけ Drive の `transaction_log.csv` を更新します。
* **証憑ファイル本体は Drive に残す:**
  重複行を消したつもりが元の領収書画像まで消えてしまうと取り返しがつかないため、削除対象は `transaction_log.csv` の行のみとし、Drive 上のファイル本体はそのまま残す仕様にしました（明細タブの各カードからも同様の確認ダイアログ経由で 1 件ずつ削除できます）。

実際にこの仕組みで重複していた 10 月 12 日の ¥5,000 を 1 件削除したところ、台帳が **4件から 3件** に減り、サマリ画面も即座に再計算されて差引収支 **-¥10,110** に更新されました。

![重複削除後の実機サマリ画面](../Docs/images/ui_summary_latest.png)
*▲ 重複行の削除後、自動で再計算された実機の収支サマリ画面（2026年分 3件 / 経費合計 ¥10,110）*

### ② AI 質問時の 503 混雑対策とテキストコピー・再入力サポート
実機検証の中で、レシート解析と同じように AI 質問タブでも Gemini API の混雑（ `503 UNAVAILABLE` ）に遭遇する場面がありました。
せっかく打った質問がエラーで流れてしまい、吹き出しの文字も選択コピーできないとストレスが大きいため、以下のサポートをまとめて入れています。

* **503 時の自動リトライ ＆ フォールバック:**
  `gemini-3.1-flash-lite` が 503 系エラーを返した場合、 **1.5 秒後に同モデルで 1 回自動リトライ** し、それでも混雑していれば **自動で `gemini-2.5-flash` へフォールバック** するようにしました。
* **エラーカードからの救済導線:**
  それでも失敗した場合は、エラーカード内に **「再送信」** （吹き出しを二重追加せず再送）、 **「入力欄に戻す」** （質問を復元して編集）、 **「質問＋データをコピー（他AIへ貼り付け）」** の 3 つのボタンを出しています。
* **長押し選択とワンタップコピー:**
  チャットの本文とエラー表示を `SelectionContainer` で囲み、長押しでの部分コピーに対応しました。吹き出し下部の **「コピー」** やユーザー発言の **「入力欄へ」** ボタンからも 1 タップで再利用できます。

## 4. Play ストア配布を見据えた「購入前注意喚起」と「キー設定ヘルプ」

ここまで動くようになり、「GitHub でソースコードを公開しつつ、自分でビルドや Google Cloud の OAuth 設定をするのが面倒な方向けに、Google Play ストアで買い切り版として公開するのもありなのでは？」という構想も見えてきました。

ただ、もしストアで有償配布する場合に一番怖いのが、 **「買ったはいいけれど、Google アカウント連携や Gemini API キーが必要だと知らなかった」「どうしても API キーが入れられずに詰まった」** というミスマッチです。

そこで、あらかじめ以下の 3 箇所に注意喚起とフォールバック導線を組み込みました。

* **初回起動画面（ `DisclaimerScreen.kt` ）:**
  免責事項と並べて **「ご利用に必要なもの（事前確認）」** カードを先頭に置き、Google アカウントが必須であること、AI 抽出・AI 質問には Gemini API キー（無料取得可）が必要なことを明記しました。
* **設定画面（ `SettingsScreen.kt` ）:**
  **「Google AI Studio でキーを取得（無料）」** ボタンから直接発行ページを開けるようにし、その下に **「キーを入れられない・お困りの方はこちら」** ダイアログを追加しました。会社・学校の Google Workspace アカウント制限時は個人の `@gmail.com` を使う対処法や、 **API キーがなくても「手入力で進む」から電帳法リネーム保存・CSV 記録・収支集計はすべて使えること** を案内しています。
* **ストア掲載文＆利用ガイドの整備（ `Docs/store_listing_and_setup_guide.md` / `Docs/user_guide.md` ）:**
  Play ストアの説明欄冒頭（折りたたまれる前の位置）に必須条件と OSS 版・ストア版の位置づけを記載するテンプレートを用意しました。

## 5. 技術的トレードオフとテスト・ビルド結果

### 割り切った点・今後の留意事項
* **AI 質問に渡す明細件数の上限:** トークン肥大化とレイテンシを抑えるため、AI 質問のコンテキストに含める明細 CSV は直近最大 500 件に制限しています（事前計算サマリは全件ベースで渡しているため、合計値自体は 500 件を超えても正確です）。
* **明細の「編集」機能:** 今回は安全に「削除」できるところまで実装しました。金額や勘定科目を後から修正したい場合は、現時点では「削除して登録し直す」か「Google Drive 上の `transaction_log.csv` を直接編集する」運用としています。
* **免責と税務境界:** AI 質問のシステムプロンプトでも、税理士法に抵触する断定的な税務判断（「これは確実に経費になります」等）を行わず、台帳整理の補助にとどめて「最終判断は税務署または税理士へご確認ください」と添えるよう制御しています。

### テスト・ビルド結果
今回追加した CSV パーサーの往復・再構築テスト（ `CsvTransactionParserTest` ）、集計テスト（ `TransactionSummaryCalculatorTest` ）、削除タグ解析・503 判定テスト（ `GeminiTransactionAdvisorTest` ）を含むユニットテスト全 23 件とデバッグ APK ビルドの結果は以下のとおりです。
