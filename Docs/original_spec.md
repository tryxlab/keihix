# 確定申告・電帳法対応レシート＆収入管理アプリ 仕様書

## 第1章：システム概要とアーキテクチャ思想

### 1.1 開発背景とコンセプト

* **課題:** 副業や個人開発における確定申告は、freee等の月額課金ソフトを使うほど取引頻度が高くない一方、放置すると確定申告期に莫大な事務コストが発生する。また、電子帳簿保存法（電帳法）への対応も必要となる。
* **コア思想: 「ゼロ・インフラ ＋ BYOK（Bring Your Own Key）」**
* サーバー代・DB運用費を完全0円にする。
* 開発者側でユーザーの機密データや領収書ファイルを一切保持しない。
* ユーザー自身のGoogle DriveとGoogle AI Studio（Gemini API）のみを利用するクライアント完結型設計。



### 1.2 全体構成図

```text
[ユーザー操作: カメラ撮影 / PDF・画像共有インテント]
       │
       ▼
[Android アプリ (クライアント)]
  ├─ 1. Google Drive API (OAuth 2.0: scope 'drive.file')
  │       └─ ユーザー自身のDrive内にアプリ専用作業領域を確保
  ├─ 2. Google AI Studio (Gemini 1.5 Flash API)
  │       └─ 画像/PDFからメタデータ（日付・金額・取引先・科目・区分）を構造化抽出
  └─ 3. ローカル検証・UI修正
          └─ 抽出結果の確認とワンタップ保存
       │
       ▼
[保存先: ユーザーの Google Drive]
  └── 確定申告_2026/
        ├── receipts/           (経費の画像・PDF)
        ├── incomes/            (収入の支払明細・請求書控えPDF)
        └── transaction_log.csv (統合トランザクションログ)

```

## 第2章：法的要件（電帳法・確定申告）のハックと免責設計

### 2.1 電子帳簿保存法（電子取引）のミニマムクリア要件

1. **検索3要件の充足:**
* 「取引年月日」「取引金額」「取引先名」による検索が可能であること。
* Google Drive上のファイル命名規則（例: `YYYYMMDD_金額_取引先.pdf`）と、同一フォルダ内の統合CSV台帳（`transaction_log.csv`）によってこの要件をクリアする。


2. **改ざん防止措置の合法化:**
* 高価なタイムスタンプ付与APIは使わず、国税庁のひな形である「電子取引データの訂正及び削除の防止に関する事務処理規程（個人事業主用）」を備え付ける方式を採用。



### 2.2 免責条項（Disclaimer）の実装

* **アプリ初回起動時ダイアログ**および**設定画面**、**リポジトリREADME**に以下を常設・合意必須化：
* 本アプリは税理士法に定める助言・税務書類作成を行うものではない。
* AIの抽出精度および電帳法・確定申告の合致性について開発者は一切保証しない。
* 最終的な税務判断・申告内容の確認はユーザーの自己責任とする。

## 第3章：データ設計（経費・収入の統合スキーマ）

### 3.1 トランザクション・メタデータ定義

経費（領収書）と収入（売上明細・請求書控え）を単一のスキーマで統合管理する。

| フィールド名 | 型 | 説明 | 例 |
| --- | --- | --- | --- |
| `id` | string (UUID) | レコードの一意識別子 | `uuid-v4` |
| `type` | string | 取引区分（`expense` または `income`） | `expense` |
| `date` | string | 取引日 / 売上計上日（YYYY-MM-DD） | `2026-10-22` |
| `amount` | integer | 取引総額（税込） | `1980` |
| `vendor` | string | 支払先店舗 / 振込元プラットフォーム | `Amazon Japan` |
| `category` | string | 勘定科目（推定候補） | `消耗品費` |
| `fee` | integer (任意) | プラットフォーム手数料（収入時） | `100` |
| `withholding_tax` | integer (任意) | 源泉徴収税額（収入時） | `0` |
| `memo` | string (任意) | 摘要・用途メモ | `開発用検証ケーブル` |
| `drive_file_id` | string | 保存されたDriveファイルのID | `1A2b3C...` |
| `drive_path` | string | Drive内の相対保存パス | `receipts/20261022_1980_Amazon.jpg` |

### 3.2 勘定科目の推定リスト

* **経費 (`expense`):** 消耗品費、通信費、旅費交通費、会議費、新聞図書費、支払手数料、雑費
* **収入 (`income`):** 売上（売掛金）、雑収入

## 第4章：Gemini 1.5 Flash による自動抽出ロジック（BYOK）

### 4.1 プロンプトおよび Structured Outputs 定義

端末内ローカルから `generativelanguage.googleapis.com` を直接呼び出す。OCRと文字列パースを小型マルチモーダルLLMの1パス処理に集約する。

```json
{
  "type": "OBJECT",
  "properties": {
    "type": {
      "type": "STRING",
      "enum": ["expense", "income"],
      "description": "領収書・レシートはexpense、売上明細や請求書控えはincome"
    },
    "date": {
      "type": "STRING",
      "description": "YYYY-MM-DD形式の取引日（収入の場合は確定日または発行日）"
    },
    "amount": {
      "type": "INTEGER",
      "description": "支払総額または売上総額（税込）"
    },
    "vendor": {
      "type": "STRING",
      "description": "店舗名、会社名、またはサービス提供元"
    },
    "category": {
      "type": "STRING",
      "description": "勘定科目の推定"
    },
    "fee": {
      "type": "INTEGER",
      "description": "差し引かれた決済手数料・プラットフォーム手数料（該当ある場合のみ）"
    },
    "withholding_tax": {
      "type": "INTEGER",
      "description": "差し引かれた源泉徴収税額（該当ある場合のみ）"
    }
  },
  "required": ["type", "date", "amount", "vendor", "category"]
}

```

### 4.2 APIキーの管理

* ユーザーがGoogle AI Studioで無料発行したキーを設定画面で入力。
* 端末内の `EncryptedSharedPreferences`（Android）等のセキュアストレージにのみ保持し、外部送信はGoogle APIエンドポイントへの通信のみに制限。

## 第5章：Google Drive ストレージ設計と確定申告連携

### 5.1 認証スコープとアクセス境界

* **採用スコープ:** `[https://www.googleapis.com/auth/drive.file](https://www.googleapis.com/auth/drive.file)`
* ユーザーのDrive全体への参照権限は要求せず、「本アプリが作成したフォルダおよびファイル」へのアクセスのみに限定し、セキュリティと安心感を担保する。

### 5.2 フォルダ・ファイル命名規則

```text
[ルートフォルダ: 確定申告_{年}]
  ├── receipts/
  │     └── {YYYYMMDD}_{金額}_{取引先}.{拡張子}
  ├── incomes/
  │     └── {YYYYMMDD}_{金額}_{取引先}.{拡張子}
  └── transaction_log.csv

```

### 5.3 年末の確定申告用エクスポート機能

* 蓄積された `transaction_log.csv` をワンタップでダウンロード/共有。
* **出力フォーマット例:**
```csv
日付,区分,勘定科目,金額,手数料,源泉徴収税,取引先,摘要,ファイルリンク
2026-10-22,経費,消耗品費,1980,,,Amazon Japan,開発用ケーブル,receipts/20261022_1980_Amazon.jpg
2026-10-31,収入,売上,50000,5000,0,note株式会社,10月度売上,incomes/20261031_50000_note株式会社.pdf

```


* これにより、国税庁「確定申告書等作成コーナー」の青色申告決算書・収支内訳書へ科目別集計値をそのまま転記可能とする。

## 第6章：UI/UXと配布戦略（GitHub & Google Play）

### 6.1 コアUXフロー

1. **共有メニュー起動 (Share Target):**
* メールやブラウザでPDF/領収書画像を開き、「共有」→ アプリを選択。
* アプリ単体起動時は「カメラ撮影」または「ファイル選択」ボタンから開始。


2. **プレビューと自動解析:**
* Gemini Flashへ送信後、1〜2秒でフォーム初期値（日付・金額・店名・科目・経費/収入トグル）を表示。


3. **確認と保存:**
* 必要に応じて手修正し、「保存」を押すとバックグラウンドでGoogle Driveへ非同期アップロード ＆ CSV追記。



### 6.2 配布・公開戦略

* **Public GitHubリポジトリ:**
* ソースコード、電帳法事務処理規程テンプレート（Markdown）、セルフビルド手順、免責事項を完全公開。


* **Google Play ストア公開:**
* 非エンジニア向けにストア審査を申請。
* 必須要件：プライバシーポリシー（Drive直結＆サーバーレスの明記）、免責事項同意画面の実装。


* **フォールバック（野良APK配布）:**
* テスター要件や審査で障壁が出た場合は即座にGitHub ReleasesでのAPK直接配布へ切り替え、そのトラブルシューティング自体をnoteの開発記事として昇華させる。
